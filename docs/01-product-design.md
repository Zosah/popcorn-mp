# 产品设计与路线图

## 1. 产品定位

“时刻在”是一个为亲密关系设计的共同生活空间。它服务于家庭、情侣、养宠家庭和稳定的小圈子，帮助成员管理日常事务并沉淀共同记忆。

产品不应被定义为单纯的清单工具。它的长期价值在于把“家里还有什么”“宠物最近怎么样”“今天吃什么”“这件事记下来”和“分享一个当下”组织到同一个有边界、有隐私的空间中。

## 2. 核心抽象：生活空间

产品和代码统一使用“空间”（`space`）作为数据隔离与协作边界。用户界面可以把空间展示为“我的家”或用户自定义的名字。

一个用户可加入多个空间，例如：

- 我们家
- 和伴侣的小家
- 两只猫的家
- 旅行搭子小圈子

每一条业务数据都必须属于一个空间。空间成员只可以访问自己具备权限的内容。

## 3. 目标用户与场景

| 用户 | 高频问题 | 首要价值 |
| --- | --- | --- |
| 家庭成员 | 冰箱还有什么、什么要过期、谁买了什么 | 减少浪费与重复购买 |
| 情侣 | 今天吃什么、想记录的小事、共同计划 | 降低生活协作成本，沉淀共同记忆 |
| 养宠家庭 | 驱虫和疫苗何时到期、体重是否变化 | 提醒照护事项，集中宠物档案 |
| 个人 | 体重、饮水、生活记录、重要资料 | 可持续记录与回顾 |

## 5. 第一阶段：家庭库存

第一阶段只完成“共同空间 + 家庭库存”的完整闭环，不同时启动所有模块。

### 用户可完成的任务

1. 首次进入后自动拥有一个默认空间。
2. 创建库存物品，填写名称、分类、数量、单位、位置和有效期。
3. 在首页查看已过期、临期、正常和无有效期的物品。
4. 搜索、按分类和位置筛选库存。
5. 编辑物品，或标记为已用完、已丢弃、已归档。
6. 邀请成员进入空间，共同维护库存。
7. 选择性为物品上传照片。

### 第一阶段不做

- 条码扫描和商品库匹配。
- 基于图片的商品识别。
- 菜谱自动推荐。
- 健康与宠物医疗建议。
- 动态评论与复杂社交关系。
- 会员付费和 AI 聊天入口。

### 有效期规则

有效期按自然日判断，第一期固定使用 `Asia/Shanghai` 时区。数据保存为 `YYYY-MM-DD` 日期字符串，不保存带小时分钟的到期时间戳。

| 条件 | 展示状态 |
| --- | --- |
| 未填写 `expiresOn` | 无有效期 |
| `expiresOn` 早于今天 | 已过期 |
| `expiresOn` 等于今天 | 今日到期 |
| 距今天 1 至 3 天 | 紧急 |
| 距今天 4 至 7 天 | 即将到期 |
| 超过 7 天 | 正常 |

物品的生命周期状态与有效期状态分离：

```text
active      正在库存中
consumed    已用完
discarded   已丢弃
archived    已归档
```

“已过期”应由 `expiresOn` 实时计算，不能存为物品状态。

## 6. 后续产品阶段

### 阶段二：家庭照护

- 多宠物基础档案：区分猫、狗与其他伙伴，记录出生日期、到家日期、绝育状态与体重。
- 成长和健康事件：疫苗、绝育、洗护、生病、就诊与外出记录。
- 宠物事件月历：集中查看历史记录、明确的下次计划与按周期推算的照护事项。
- 持续照护事件：体内驱虫、体外驱虫，以及根据最近一次记录推算下次日期。
- 每日吃喝拉撒：记录进食、饮水、便便和尿尿的次数、时间与简要情况。
- 吃喝拉撒用品集合：主粮、罐头、冻干、汤包、猫砂与猫砂种类，支持正在用、爱吃、吃过、种草和拔草状态。
- 个人体重、围度、习惯与目标记录。
- 统一提醒中心和微信订阅消息。

### 阶段三：共同生活内容

- 常做菜谱、冰箱库存与今日菜单。
- 按菜单生成购物清单。
- 图文动态、悄悄话、评论和互动策略。
- 重要记录、标签组、搜索、收藏和归档。

### 阶段四：智能与商业化

- 基于库存和临期食材的菜谱建议。
- 家庭周报、宠物照护摘要、生活回顾。
- 会员权益、AI 使用量和支付能力。

## 7. 隐私与互动规则

家庭空间不是默认公开空间。每一条敏感内容都需要独立定义可见范围：

```text
private     仅创建者可见
selected    创建者指定的成员可见
space       当前空间全部成员可见
```

健康数据、身体指标、病历、悄悄话和私密图片默认使用 `private` 或 `selected`。不应仅因用户属于同一空间，就自动向所有成员公开。

动态的互动策略独立于可见范围：

```text
none        不可互动，只作为记录
reactions   可表态，不可评论
comments    可表态、可评论
```

## 8. AI 与会员原则

AI 是现有任务流的增强能力，不是第一期的产品入口。优先考虑能减少明确操作成本的能力：

- 根据临期食材和库存推荐晚餐方案。
- 根据菜单生成购物清单。
- 把多条记录整理成家庭周报或月度回顾。
- 汇总宠物体重、疫苗和驱虫事项。
- 帮助归类重要记录和标签。

涉及健康与医疗信息时，必须逐次获得用户授权，说明发送的数据范围，并明确“仅供生活管理参考，不构成医疗建议”。

免费版应覆盖核心记录、单空间基础协作与有效期提醒。VIP 更适合承载有明确成本或高级效率价值的能力：多个空间、更高成员数、更大媒体容量、长期归档、高级统计、数据导出、AI 用量和家庭回顾。

## 9. 待决定事项

1. 空间邀请第一期采用邀请码、二维码，还是两者都支持。
2. 库存物品图片是否是第一期必备能力。
3. 临期默认阈值是否采用 3 天和 7 天，是否允许空间级自定义。
4. 第一阶段是否先只支持食品与日用品，还是直接支持药品与宠物用品分类。
5. 是否将“购物清单”作为库存第一阶段的最后一个小功能。
