# 功能清单与快捷配置设计

> 状态：v1.26.1 已实现，待体验版真机验收
> 范围：个人页功能目录、功能清单、首页快捷入口、底部导航、拖拽配置与空间级同步

## 1. 设计结论

功能配置不是一个“设置表单”，而是一张可编辑的桌面：

- 上方是完整功能池，所有功能使用 2～3 个字的名字展示。
- 下方同时展示两个投放区域：「首页快捷」4 个位置、「底部导航」中间 3 个位置。
- 用户长按功能池中的功能，直接拖入目标区域。
- 用户也可以拖动已有位置，在本区域内排序；放入已占用位置时自动交换。
- 所有拖动只修改本地草稿，不产生请求。
- 页面底部固定「保存配置」，统一提交一次。

个人页不承担配置操作，只负责浏览与进入功能：

- 设置入口固定在右上角。
- 头像、昵称、共同空间之后直接展示功能目录。
- 一级分类只展示标题和一句说明，不出现分类图标。
- 功能行展示名称、简短描述和进入箭头。
- 「功能清单」「功能配置」「提醒设置」等管理入口收进设置页，不再重复铺在个人页。

规则：

- 功能目录只展示一级功能；旅行、计划、健身、账单、宠物二级能力从父功能内部进入。
- 二级功能仍可单独放入首页快捷或底部导航。

## 3. 拖拽交互

### 3.1 从功能池拖入

- 长按约 280ms 进入拖拽，出现轻微震动和悬浮卡片。
- 拖到首页位置：替换目标位置。
- 拖到底部导航位置：替换目标位置。
- 「提醒」「宠物月历」仅允许首页，拖到底栏时显示阻断态并提示。
- 支持的功能可以在首页和底栏同时出现；同一区域不允许重复。
- 若功能已经存在于同一区域，拖到另一个位置时执行交换，不产生重复入口。

### 3.2 区域内排序

- 首页 4 个位置之间可拖动排序。
- 底栏中间 3 个位置之间可拖动排序。
- 「家」「我的」是固定项，不参与拖拽。
- 拖拽过程锁定页面纵向滚动，避免手势冲突。

### 3.3 草稿与保存

- 任意拖拽只更新 `config`，同时把 `dirty` 置为 `true`。
- 保存前不调用 API，页面显示「有未保存修改」。
- 点击「保存配置」后一次性提交 `homeSlots + tabSlots`。
- 保存成功更新版本号，状态变为「已同步到空间」。
- 保存失败保留当前草稿，不自动回滚。
- 版本冲突时保留草稿，并提供「载入最新」；用户确认后才放弃本地调整。
- 「恢复默认」只替换当前草稿，仍需点击保存。

## 4. 数据模型

前端只保存功能 ID 和顺序，标题、图标、描述、分类、路由全部来自统一功能注册表。

```json
{
  "homeSlots": ["inventory", "todo", "fitness", "pets"],
  "tabSlots": ["pets", "expense", "travel"],
  "version": 12,
  "updatedAt": "2026-11-01T08:44:38.174Z"
}
```

约束：

- `homeSlots` 固定 4 个。
- `tabSlots` 固定 3 个。
- 同一区域不允许重复。
- 首页与底栏之间允许重复。
- 功能 ID 必须来自服务端白名单。
- 配置按「空间 + 用户」隔离。

接口：

```text
GET /spaces/{spaceId}/feature-settings
PUT /spaces/{spaceId}/feature-settings
```

保存继续使用：

- `If-Match: "<version>"`
- `Idempotency-Key`
- `409 VERSION_CONFLICT`
- `422 VALIDATION_FAILED`

## 6. 验收标准

### 功能

1. 配置页顶部展示全部可选功能，名称均为 2～3 个字的短标签。
2. 功能池可以拖入首页和底部导航。
3. 首页与底栏各自支持区域内排序。
4. 不支持的底栏功能出现阻断态，不污染草稿。
5. 同一区域不会出现重复功能。
6. 任意拖拽不自动保存。
7. 点击保存后才写服务端，版本递增。
8. 恢复默认只改草稿。
9. 保存失败保留草稿，版本冲突可以载入最新。
10. 个人页设置入口位于右上角。
11. 个人页一级分类只有标题和描述，没有分类图标。
12. 设置页承载个人资料、共同空间、功能配置和提醒设置。

### 视觉与交互

1. 首次加载使用统一 loading，避免白屏和闪烁。
2. 页面无横向溢出。
3. 保存条不遮挡底栏拖放区，滚动到底部可以完整操作。
4. 长按拖拽有悬浮卡片、目标高亮和阻断反馈。
5. 小屏下功能池使用稳定的 4 列布局，短标签不换行。

### 数据

1. Demo 模式本机持久化。
2. HTTP 模式按空间和用户隔离。
3. 旧 `app-tab-settings` 接口仅更新底栏，并保留首页配置。
4. 非法功能、重复槽位、缺失槽位和旧版本写入均被拒绝。

## 7. 本轮非目标

- 任意数量快捷入口。
- 页面内部模块排序。
- 功能搜索。
- 跨设备实时协作拖拽。
- 图片与 COS 相关改动。
