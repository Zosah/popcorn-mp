# 功能清单与快捷配置设计

> 状态：方案设计稿，待进入实现切片
> 版本目标：v1.26.0
> 范围：个人页入口、功能清单、首页快捷入口、底部导航快捷入口、拖拽排序与空间级配置同步

## 1. 结论先行

把当前「底部导航」页面升级为统一的「功能配置」，同时新增独立的「功能清单」页面。两者职责必须分开：

- **功能清单**：回答“这个产品有哪些功能”，用于浏览和直接打开全部核心能力。
- **功能配置**：回答“哪些功能放在手边”，只管理首页快捷入口和底部导航，不承担完整功能目录。

推荐结构：

```text
个人页
  ├─ 功能清单            浏览全部功能，直接打开
  ├─ 功能配置            配置首页快捷入口与底部导航
  └─ 提醒设置            保留现有设置
```

首页和底部导航都只保存“功能 ID + 顺序”，不保存页面路径、标题或图标。标题、图标、分类和路由统一由前端功能注册表维护。

## 2. 当前问题

当前 `tab-settings` 页面存在四个问题：

1. 页面标题叫「底部导航」，但它无法表达首页快捷入口的配置需求。
2. “选择位置 → 再向下翻可选功能”的交互路径过长，需要用户先理解槽位，再理解功能。
3. 功能列表混用“一级入口 / 二级功能”，这不是用户心智分类。
4. 页面把预览、槽位、完整候选列表全部纵向铺开，主次不清；底部导航只有一个入口，但配置页本身像功能大厅。

## 3. 产品边界

### 3.1 可配置的区域

| 区域 | 固定项 | 可配置项 | 数量 |
| --- | --- | --- | --- |
| 首页快捷入口 | 无 | 功能快捷入口 | 4 个 |
| 底部导航 | 家、我的 | 中间快捷入口 | 3 个 |

### 3.2 不在本切片内

- 不允许用户自定义功能顺序之外的页面内容。
- 不允许配置页面内部按钮、卡片顺序或数据模块。
- 第一版不开放“拖动功能库卡片跨区域放入槽位”，避免与纵向滚动冲突。
- 第一版不做任意数量的快捷入口，首页固定 4 个、底栏固定 3 个，保证布局稳定。

## 4. 功能分类

### 4.1 用户可见分类

只保留三个常用分类，避免分类体系比功能本身更复杂。

| 分类 | 定义 | 功能 |
| --- | --- | --- |
| 工具 | 解决一件具体的家务或生活问题 | 家庭库存、今天吃什么、提醒设置 |
| 备忘 | 记录打算、过程、花费与共同回忆 | 待办与小计划、旅行准备、小计划、健身计划、我们的账单、生活记录 |
| 成员 | 围绕家庭成员本身的功能 | 宠物、宠物照护、宠物日常、宠物月历 |

### 4.2 功能注册表

前端建立唯一功能注册表 `feature-catalog`，至少包含：

```ts
interface FeatureDefinition {
  id: string
  label: string
  shortLabel: string
  description: string
  category: 'tool' | 'memo' | 'member'
  icon: string
  tone: string
  path: string
  query?: Record<string, string>
  quickEligible: boolean
}
```

`feature-catalog` 同时服务于：

- 功能清单的展示与分类。
- 功能配置的可选项。
- 首页快捷入口渲染。
- 底部导航渲染。
- 页面跳转与功能打开埋点。

现有 `app-tab-config.ts` 中的 `APP_TAB_OPTIONS` 应收敛到该注册表，避免同一功能同时维护标题、图标、路径和分类多份数据。

### 4.3 快速入口资格

- 工具、备忘、成员三个分类中的核心功能默认允许加入首页和底栏。
- 「家」「我的」固定存在，不进入候选功能库。
- 「功能清单」「功能配置」「共同空间」属于管理能力，不加入快捷配置候选。
- 同一区域内不允许重复功能；首页和底栏之间允许重复，并显示轻量状态提示。

## 5. 页面设计

### 5.1 个人页

个人页保持现有“头像 + 共同空间 + 设置”的简洁结构，不新增功能墙。设置区改为：

```text
功能与设置
  [icon] 功能清单                        查看全部功能          ›
  [icon] 功能配置                        首页与底栏            ›
  [icon] 提醒设置                        通知与订阅            ›
```

入口顺序固定：功能清单在前，功能配置在后。这样用户先知道有什么，再决定放什么。

### 5.2 功能清单页

页面标题：`功能清单`

页面结构：

```text
┌──────────────────────────────────┐
│ 我们的功能                        │
│ 从这里找到全部生活能力     配置快捷 › │
├──────────────────────────────────┤
│ 工具                              │
│  家庭库存        家里的物品与临期提醒  › │
│  今天吃什么      菜单、推荐和做饭模式  › │
│  提醒设置        通知与订阅偏好        › │
├──────────────────────────────────┤
│ 备忘                              │
│  待办与小计划    旅行、健身、账单      › │
│  生活记录        共同回忆与重要资料    › │
├──────────────────────────────────┤
│ 成员                              │
│  宠物            档案、照护与日常      › │
└──────────────────────────────────┘
```

规则：

- 一级功能直接展示；旅行准备、小计划、健身、账单等二级功能收在一级功能内部，不重复铺满清单。
- 每个功能项点击后直接打开目标页面。
- 功能项显示“首页快捷 / 底栏”小状态，便于理解它已经被放到哪里。
- 顶部只保留一个「配置快捷」文字入口，不放大型 Hero 或运营卡片。
- 第一版不做搜索；功能数量超过 20 个后再增加搜索。

### 5.3 功能配置页

页面标题：`功能配置`

页面首页只保留三个层级：

1. 区域切换：首页快捷 / 底部导航。
2. 当前布局：可直接拖拽排序的槽位。
3. 更换功能：点击槽位后从底部面板按分类选择。

推荐线框：

```text
┌──────────────────────────────────┐
│ 功能配置                   已同步  │
│ 把每天最常用的功能放到手边          │
├──────────────────────────────────┤
│ [ 首页快捷 4/4 ] [ 底部导航 3/3 ]  │
├──────────────────────────────────┤
│ 当前布局                          │
│                                  │
│  ╭────╮  ╭────╮  ╭────╮  ╭────╮  │
│  │记录│  │库存│  │待办│  │宠物│  │
│  ╰────╯  ╰────╯  ╰────╯  ╰────╯  │
│      长按拖动排序 · 轻触更换        │
│                                  │
│  恢复默认                          │
├──────────────────────────────────┤
│ 功能库入口                        │
│  [从工具、备忘、成员中选择功能]      │
└──────────────────────────────────┘
```

底栏模式预览：

```text
┌──────────────────────────────────┐
│ 当前底栏                          │
│  家   [宠物] [记录] [待办]   我的  │
│       可拖动      固定             │
└──────────────────────────────────┘
```

#### 拖拽规则

- 首页快捷：4 个槽位横向拖动排序。
- 底部导航：中间 3 个槽位横向拖动排序；家、我的固定不可拖。
- 长按约 350ms 后进入拖动；触发轻震动，卡片抬起并出现阴影。
- 拖动过程只改变本地草稿，松手后保存一次，避免每一步都请求服务端。
- 拖动时锁定页面纵向滚动。
- 点击槽位打开功能选择面板；选择后立即替换并保存。
- 点击「恢复默认」需要二次确认。

第一版不支持“把下方功能卡片直接拖进槽位”，原因：

- 小程序长列表滚动与跨区域拖拽容易冲突。
- 点击槽位再从面板选择已经能完成替换，且更容易理解。
- 后续若要支持跨区域拖拽，可在此基础上增加，不影响数据模型。

#### 功能选择面板

从底部弹出，按工具、备忘、成员分组：

```text
┌──────────────────────────────────┐
│ 更换第二个底栏入口            关闭 │
│                                  │
│ 工具                              │
│  家庭库存       已在首页快捷      选择 │
│  今天吃什么                    选择 │
│                                  │
│ 备忘                              │
│  生活记录                      选择 │
│  待办与小计划                  选择 │
│                                  │
│ 成员                              │
│  宠物           当前入口          选择 │
└──────────────────────────────────┘
```

- 同一区域已使用的功能不可重复选择，显示“已在第 N 个位置”。
- 跨区域使用的功能允许选择，显示“已用于首页快捷”或“已用于底栏”。
- 空槽位显示虚线卡片和加号。

## 6. 交互状态

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 页面骨架或统一的短 loading，不闪白 |
| 有缓存 | 立即回显本机配置，后台同步服务端 |
| 同步中 | 右上角显示“同步中” |
| 已同步 | 显示“已同步到空间” |
| 同步失败 | 保留本机版本，显示重试入口 |
| 版本冲突 | 自动加载最新版本，并提示“配置已在别处更新” |
| 登录失效 | 跳转登录，不静默覆盖本机草稿 |
| 未登录 | 可以查看功能清单；功能配置需要登录 |

删除、拖拽、替换三种操作统一使用同一套乐观更新与回滚策略。

## 7. 数据与接口设计

### 7.1 配置模型

```json
{
  "homeSlots": ["journal", "inventory", "todo", "pets"],
  "tabSlots": ["pets", "journal", "todo"],
  "version": 2,
  "updatedAt": "2026-11-01T08:00:00Z"
}
```

- `homeSlots` 固定 4 个，不允许重复。
- `tabSlots` 固定 3 个，不允许重复。
- 首页与底栏之间不要求互斥。
- 所有 ID 必须来自服务端白名单。

### 7.2 API 演进

建议新增语义更准确的接口，同时保留旧接口一个版本用于兼容：

```text
GET /spaces/{spaceId}/feature-settings
PUT /spaces/{spaceId}/feature-settings
```

旧接口 `/app-tab-settings` 暂时作为别名，只返回和接收底栏三个槽位；新版本前端全部切到 `feature-settings`。

PUT 请求：

```json
{
  "homeSlots": ["journal", "inventory", "todo", "pets"],
  "tabSlots": ["pets", "journal", "todo"]
}
```

继续使用：

- `If-Match: "<version>"`
- `Idempotency-Key`
- 409 `VERSION_CONFLICT`
- 422 `VALIDATION_FAILED`

### 7.3 数据库演进

当前 `t_app_tab_settings` 已经按“空间 + 用户”一行保存 3 个槽位，结构和版本控制可以直接复用。本切片建议在原表增加 4 个首页槽位，而不是立即拆成多张表：

```text
home_slot1 VARCHAR(32) NOT NULL DEFAULT 'journal'
home_slot2 VARCHAR(32) NOT NULL DEFAULT 'inventory'
home_slot3 VARCHAR(32) NOT NULL DEFAULT 'todo'
home_slot4 VARCHAR(32) NOT NULL DEFAULT 'pets'
```

理由：

- 目前只有两张固定布局，槽位数量稳定，单行模型足够。
- 乐观锁、幂等、权限过滤都已有现成实现，扩展字段风险最低。
- 真正需要任意数量和任意区域时，再迁移到 `settings + items` 两张表，不在当前阶段过度设计。

迁移默认值与当前首页硬编码顺序完全一致，已有用户升级后视觉不变。

## 9. 验收标准

### 功能

1. 个人页可进入功能清单和功能配置。
2. 功能清单按工具、备忘、成员分类展示，所有功能可直接打开。
3. 首页 4 个快捷入口可拖拽排序、点击更换、恢复默认。
4. 底栏中间 3 个入口可拖拽排序、点击更换；家、我的不可修改。
5. 同一区域不会出现重复功能。
6. 首页与底栏修改后立即生效，切换页面不闪烁。
7. Demo 模式、HTTP 模式、空间切换和版本冲突行为一致。

### 数据

1. 配置按“空间 + 用户”隔离。
2. 配置保存使用 If-Match 与 Idempotency-Key。
3. 旧配置迁移后首页与底栏保持原样。
4. 非法功能 ID、重复槽位和缺失槽位均被服务端拒绝。

### 视觉与交互

1. 配置页首屏不需要滚动即可看到当前布局和操作说明。
2. 拖拽有抬起态、目标位移动画和保存反馈。
3. 点击更换不会离开页面，底部面板可取消。
4. 功能清单不做功能墙，不出现重复的二级功能入口。

## 12. 推荐决策

采用“功能注册表 + 单页双区域配置 + 槽位拖拽 + 点击更换”的方案。它比继续扩展现有长列表更容易理解，也比一开始引入通用配置引擎更轻。第一版只解决三个问题：

1. 所有功能找得到。
2. 首页和底栏能按个人习惯排列。
3. 配置同步可靠、不会因为拖拽产生大量请求。
