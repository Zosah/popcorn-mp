# 前端 MVP Demo 1.5 设计与运行

> 产品描述：我回来啦，把日子安放在一起。
>
> 本文是当前前端 Demo 的产品、交互与视觉基线。页面继续演进时，应先判断是否仍在表达“共同生活空间”，避免退回单一库存工具或通用后台模板。

Demo 1.5 保留完整本机体验，同时把账号、资料、会话、默认空间、成员、邀请、库存、待办和生活记录接入真实 Go API。`demoMode: true` 时所有页面继续离线可演示；`demoMode: false` 时登录、个人中心、空间/邀请、库存、待办和生活记录走 HTTP，宠物、菜单和提醒仍使用本地存储。首次微信登录会进入资料完善，服务端在同一次事务中创建用户、默认空间和 owner 成员关系；空间 owner 可重命名、生成 10 位一次性邀请码并查看成员，另一用户可在登录后预览并接受邀请。库存、待办和生活记录支持服务端游标分页、摘要、If-Match 版本冲突、幂等重试和软删除；待办还支持准备项勾选、完成/重开与账单自动完成，生活记录支持空间公开与仅自己可见。

## 1. 这次 Demo 要回答什么

Demo 0.2 已经把首页从单一库存工具改成共同生活空间，但手账和旧杂志风格偏克制、偏静态，缺少用户希望的轻松、活泼与陪伴感。Demo 0.3 参考健康类生活应用的视觉语言，用可爱的状态角色、白色圆角卡片和彩色数据图形表达共同生活。

Demo 0.3 不急着增加接口，而是先确认三件事：

1. 用户打开后能感到“回到我们的家”，而不是进入管理后台。
2. 库存、吃饭、宠物和生活记录属于同一个共同生活叙事。
3. 在后端 B1/B2 完成前，核心页面也要足够接近真实产品，用于讨论范围、风格和交互顺序。

## 2. 产品主叙事

“时刻在”不是库存清单，而是家庭、情侣、养宠家庭与亲密小圈子的共同生活空间。

首页用“我回来啦”承接一天结束后回到家的情绪，再依次回答：

- 家里现在有什么要紧的事。
- 今天一起吃什么、照顾谁、完成什么。
- 共同生活里有哪些持续发生的数据。
- 最近有什么值得留下来的小事。

库存是第一条可落地的业务闭环，但不是整个产品的身份。菜单、宠物和提醒继续用本机持久化验证真实操作手感；生活记录已切换为空间共享数据，页面会明确显示“正在同步 / 已同步 / 同步失败”，不再把云端能力描述成本机数据。

## 3. 信息架构

底部保留四个核心入口：

| 入口 | 页面职责 | Demo 1.5 状态 |
| --- | --- | --- |
| 家 | 今日问候、生活影像、库存与待办双重点、小入口和最近记录 | 首页摘要读取各模块 Gateway |
| 库存 | 到期分组、筛选、物品列表、新增、详情与历史恢复 | Demo/HTTP 双模式；空间成员共享 |
| 记录 | 生活点滴、重要记录、可见性和记录增删改查 | 本地 Mock 数据闭环 |
| 我的 | 登录注册、当前身份、共同空间、成员、待办入口、邀请、提醒设置和 Demo 工具 | Demo/HTTP 双模式；账号、资料、空间、库存、待办和生活记录可用真实服务端 |

“家”必须是默认入口。用户不需要先理解功能模块，先看到共同生活正在发生什么，再进入具体事务。

## 4. 核心页面

### 家

- 根据上海时区显示问候、日期和星期，以“今日也慢慢来”的生活化问候作为首屏情绪入口。
- 用一张生活影像卡承接“把普通的一天轻轻收好”，并直接进入生活记录。
- 首屏只保留“家庭库存”和“待办与小计划”两个重点，先回答今天最需要处理什么。
- 待办、菜单、宠物和记录收进轻量小入口，避免首屏出现功能墙。
- 通过最近记录把库存与待办信息重新落回日常感受。

### 库存

- 摘要使用紧凑的圆角状态卡，物品仍使用易扫描的连续清单。
- 状态颜色只帮助扫描，必须同时保留“已过期 N 天”“还剩 N 天”等文字。
- 新增、编辑、用完、丢弃、归档、历史恢复和重置均保留本地交互。

### 记录

- 以日期和时间轴组织生活点滴，体现“共同记忆”而非社交动态流。
- 生活点滴和重要记录都支持新增、查看详情、编辑和删除，内容、可见范围与更新时间保存在本地。
- 重要记录按“家的资料 / 健康资料 / 宠物资料 / 其他资料”分组，适合保存需要长期查找的信息。
- 明确哪些内容对空间成员可见，为后续权限模型留出位置。

### 我的与空间

- “我的”页同时表达个人身份、待办进度和当前共同空间，不把三类信息混在一起。
- 未登录时显示访客身份与明确的登录入口；登录后展示真实昵称、昵称首字头像和已登录状态。
- Demo 模式通过本机账号模拟微信入口；HTTP 模式由服务端 `code2session` 或 local mock 建立可撤销会话。
- 首次登录进入昵称与头像配色表单；资料保存后写入服务端，账号页可恢复会话、编辑资料、退出和清除本机登录信息。
- 空间与邀请是首屏主动作，提醒和 Demo 工具收进次级设置卡。
- 空间页展示名称、当前成员、角色、邀请规则和隐私边界；非成员访问统一按不存在处理。
- owner 可重命名空间、生成 10 位一次性邀请码、复制/分享并预览接收方页面；member 只能查看和加入，不能管理空间。
- 邀请落地页支持分享路径自动带码、手动输入和公开预览；登录后接受邀请，过期、无效、已使用和已是成员均有明确状态。

### 待办与小计划

- “我的”页提供“待办与小计划”入口，并显示未完成数量和旅行准备数量；进入后可在全部、旅行准备、小计划、健身、今天吃什么和我们的账单之间筛选。
- 一个统一表单承载五类记录：旅行为目的地、出发日期和逐项准备清单；小计划为日期和补充说明；健身包含运动、时长与按运动类型粗略估算的热量；吃饭包含餐次、备注和本地“换一个”推荐；账单包含金额、购买地点与买了什么。
- 列表支持直接勾选完成、逐项勾选旅行准备清单、点击编辑和长按删除；已完成事项排在后面，过期日期会明确标注。
- 账单按“已记账”保存并显示累计金额，不计入“还有几件没做”；健身热量按运动类型和时长粗略估算且可手动调整，只作日常记录，不作为医学建议。
- Demo 模式下待办、清单勾选和账单使用独立本地存储键；HTTP 模式下通过 `TodoGateway` 写入空间并在成员间共享，页面显示“正在同步 / 已同步 / 同步失败”。
- 待办列表自动翻完游标分页；编辑使用 ETag 与 `If-Match`，遇到 409 会自动刷新最新详情，避免静默覆盖另一成员的修改。

### 宠物

- 顶部支持在多个宠物档案之间切换，也可新增猫、狗或其他伙伴；首页始终读取当前宠物。
- “档案”集中展示出生、到家、绝育、体重和成长事件时间线。
- “照护”持续记录内外驱，并按照 90 天和 30 天 Demo 周期推算下次日期。
- 独立事件表单支持事件类型、日期、标题、备注、机构、费用和下次计划。
- 时间线和月历中的真实事件可进入详情，并支持编辑和删除；修改会同步反映在两个入口。
- 宠物月历按月展示历史事件、明确的下次计划和周期照护日期，并可从选中日期继续新增记录。
- “吃喝拉撒”按上海自然日汇总进食、饮水、便便和尿尿，可重复记录次数和最近情况。
- “吃喝拉撒”管理主粮、罐头、冻干、汤包和猫砂集合，条目可在正在用、爱吃、吃过、种草和拔草之间切换。
- 首页宠物卡读取同一份本地状态，展示最新体重和优先级最高的内外驱提醒。
- 医疗相关内容只作生活记录，页面明确提示不构成诊疗建议。

### 表单与详情

- 保留库存本地闭环所需的新增、编辑和详情操作。
- 菜单支持详情、人份调整、食材备料勾选和表单编辑；重要记录复用同一套记录详情与编辑机制。
- 视觉沿用 v5「柔光玻璃生活手帐」，输入区域使用柔光玻璃容器、圆角分段选择、清晰字段分组和统一细线图标。

## 5. 视觉基线

> 2026-10-26 起以 v5「柔光玻璃生活手帐」为准；旧版视觉描述已被本节替代。

整体方向是“清透、圆润、有生活温度的轻玻璃手帐”：页面底层是低饱和薰衣草、薄荷、暖桃交织的柔雾渐变，内容层用半透明玻璃卡、白色内高光和大圆角建立层级。可爱感来自柔和配色、圆润图标容器与少量生活影像，不靠高饱和色块或装饰贴纸堆叠。它仍是每天要用的家庭工具，文字对比、信息顺序和操作效率优先于视觉效果。

| 角色 | 取值或原则 |
| --- | --- |
| 页面底色 | `#f5f2fa` 为基准，叠加薰衣草、薄荷、暖桃柔雾渐变 |
| 主文字 | `#292737`，近墨紫黑；次级文字 `#615f70`，弱信息 `#9592a4` |
| 主强调色 | `#7569e8` 薰衣草紫，深阶 `#665bd7`；用于主动作、选中态和关键数据 |
| 辅助色 | `#50b7ae` 薄荷、`#ee9eb4` 柔粉、`#d99c3f` 暖金；只做分区和状态辅助，状态始终保留文字 |
| 内容容器 | 默认大圆角玻璃卡（32–42rpx），半透明白色渐变、轻阴影和内侧高光；同屏只让真正重要的卡获得更强层级 |
| 玻璃兼容 | `backdrop-filter` 只作增强；卡片的底色、边框和文字必须在不支持模糊时仍清楚可读 |
| 图片 | 保留叙事影像卡和生活插画；每页最多一个主影像锚点，并就近标注示例/来源 |
| 功能图标 | 统一使用 Lucide Static 0.468.0 线性图标，放入柔和图标容器；辅助文字识别，不单独承担关键操作 |
| 底部导航 | 悬浮玻璃胶囊，4 个入口 + 当前项柔和渐变选中态；内容底部必须为 128rpx 导航与安全区留出空间 |
| 动效 | 只反馈切换、完成和保存等真实操作；不做每张卡依次浮入的装饰动画 |

后续页面应避免：

- 把玻璃理解成低对比度：文字叠在复杂背景上、主要信息被透明层冲淡。
- 每个模块都堆成同样尺寸、同样强度的玻璃卡，导致没有主次。
- 高饱和颜色铺满整张页面，或只用颜色区分业务状态而不保留状态文字。
- 使用超出内容需要的发光、厚重多层阴影或装饰性图片背景。
- 直接使用系统 emoji，导致不同设备视觉不一致。
- 每个空态都强行配图，或把插画当作填充留白的装饰贴纸。
- 把每个标题、字段和按钮都配图标，形成拥挤的图标墙。
- 把公版艺术示例伪装成用户真实照片；涉及宠物、物品和记录时必须明确标注。

## 6. 数据与后端边界

当前目录统一为 `src/`，不再使用 `miniprogram/`。

账号与空间链路已拆成两层：页面调用 `services/auth.ts` 与 `services/space-gateway.ts`，底层通过 `transport.ts` / `http.ts` 发送带 Bearer Token 与 `X-Request-Id` 的请求；Demo 分支继续调用 `demo-*` 本机实现。会话 Token 与用户快照保存在 `stores/session.ts`，服务端始终是权限与邀请状态的权威来源。

库存、待办和生活记录分别通过 `InventoryGateway`、`TodoGateway`、`JournalGateway` 访问数据，三者都支持 Demo 与 HTTP 实现。HTTP 模式统一处理 ETag 乐观锁、`If-Match`、幂等键、409 冲突刷新、游标分页和软删除；生活记录在数据库查询层按公开/私密范围过滤，私密记录对其他成员统一表现为不存在。Demo 模式继续持久化到小程序本地存储，便于离线演示和页面开发。首页读取 Gateway 返回的数据，不直接依赖具体存储实现。宠物、菜单和提醒继续使用独立本地存储键。

OpenAPI 是前后端唯一接口契约。库存和待办已按契约接入真实服务端；后续新增模块继续沿用 Gateway 分层、幂等和乐观锁约定。在模块真正接入 HTTP 前，不能把本机业务数据描述成已跨设备同步。

## 9. 视觉验收清单

- 打开即进入“家”，首屏主标题是“我回来啦”。
- “我的”页未登录时显示访客身份和“账号与登录”入口，登录后昵称、头像首字和空间成员身份同步更新。
- 首次登录可创建本机账号，昵称为空时阻止提交；退出后本机账号仍在，可再次一键登录。
- 账号资料可编辑，清除本机账号只影响登录资料，不影响其他 Demo 数据。
- 四个 Tab 分别是家、库存、记录、我的。
- 自定义底部 Tab 不遮挡最后一条内容或悬浮操作按钮，带底部安全区的设备也应保留足够间距。
- 菜单、宠物、记录表单、空间和提醒设置页能够返回来源页；直接打开子页时能够回到对应 Tab。
- Demo 模式的空间页可以复制和分享当前邀请码，邀请分享路径能打开接收方页面并自动完成格式校验。
- HTTP 模式下 owner 可读取真实空间与成员、重命名并创建 10 位邀请码；member 不显示管理操作。
- 第二个 mock 用户登录后可预览并接受邀请，会话中出现共同空间；同一邀请码再次预览显示已使用。
- 宠物页可在档案、照护和吃喝拉撒之间切换，新增记录后重新进入页面仍然存在。
- 宠物页可切换示例伙伴，新增伙伴后首页和宠物页均读取当前档案。
- 事件表单可保存机构、费用与下次计划；月历能在跨月切换后显示对应日期的事项。
- 时间线和月历均可进入事件详情；编辑或删除后，返回来源页面时内容即时更新。
- 重要记录可切换分类、可见范围并完成新增、详情、编辑和删除；HTTP 模式下两个空间成员共享公开记录，私密记录仅创建者可见。
- 菜单可完成新增、详情、编辑和删除；人份与食材备料勾选在返回、重进和编辑后保持。
- “我的”页的“待办与小计划”显示准确未完成数量；五类分类均可查看、新增和完成，重新进入后状态仍在。
- HTTP 模式下两个空间成员能看到同一份待办；编辑页显示加载状态，保存、删除或勾选时显示同步结果。
- 旅行待办可填写目的地、日期和多行准备清单，清单项可逐项勾选；账单可记录金额和购买地点，且不计入未完成待办。
- “恢复 Demo 初始数据”后库存、宠物、记录、菜单、待办、提醒和空间名称都回到可识别的初始状态。
- 内外驱的最近日期和下次日期随新增记录更新，过期和临近状态同时保留文字提示。
- 主粮、罐头、冻干、汤包和猫砂可筛选，集合状态可修改。
- 进食、饮水、便便和尿尿可在同一天重复记录，今日次数、最近内容和时间即时更新。
- 页面在小屏设备上没有横向溢出、文字截断或底部 Tab 遮挡。
- 首页信息能按“今天状态 → 晚餐 → 生活数据 → 最近记录”顺序阅读。
- 库存状态在不依赖颜色的情况下仍可理解。
- 静态预览能力不会让用户误以为可以保存或同步数据。
- 页面使用柔雾渐变与适度玻璃层，主次层级由尺寸、留白、色温和容器强度共同建立。
- 关闭或无法使用 `backdrop-filter` 时，玻璃卡上的文字与操作仍然清楚可读。
- 首页首屏聚焦今日问候、生活影像、库存与待办双重点，小入口没有反客为主。
- 待办页用生活分类卡表达类别与完成进度，筛选和新增入口无需长距离滚动才能找到。
- “我的”页首屏优先呈现身份、待办进度、空间和邀请，提醒与 Demo 工具处于次级位置。
- 叙事主图每页最多一处；小幅插画只用于空态、邀请或身份收尾，并明确标注示例/来源。
- 所有公版艺术示例均有就近标识，作品与授权信息可在 `assets/credits.json` 追溯。
- 图标风格、线宽和尺寸一致，常规区域不出现图标替代文字或图标密度过高的情况。
