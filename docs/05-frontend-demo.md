# 前端 MVP Demo 1.1 设计与运行

> 产品描述：我回来啦，把日子安放在一起。
>
> 本文是当前前端 Demo 的产品、交互与视觉基线。页面继续演进时，应先判断是否仍在表达“共同生活空间”，避免退回单一库存工具或通用后台模板。

Demo 1.1 已把前端主要日常链路串成可操作的单机 MVP：库存、宠物、菜单、生活点滴、重要记录、待办与小计划、提醒、空间和邀请均有本地持久化体验；菜单支持新增、编辑、删除、人份调整与食材备料勾选，重要记录支持分类、可见范围、详情、编辑和删除。“我的”页可一键恢复全部 Demo 初始数据。当前数据只保存在当前设备，后端、数据库和跨设备同步尚未接入。

## 1. 这次 Demo 要回答什么

Demo 0.2 已经把首页从单一库存工具改成共同生活空间，但手账和旧杂志风格偏克制、偏静态，缺少用户希望的轻松、活泼与陪伴感。Demo 0.3 参考健康类生活应用的视觉语言，用可爱的状态角色、白色圆角卡片和彩色数据图形表达共同生活。

Demo 0.3 不急着增加接口，而是先确认三件事：

1. 用户打开后能感到“回到我们的家”，而不是进入管理后台。
2. 库存、吃饭、宠物和生活记录属于同一个共同生活叙事。
3. 即使后端尚未完成，核心页面已经足够接近真实产品，可用于讨论范围、风格和交互顺序。

## 2. 产品主叙事

“时刻在”不是库存清单，而是家庭、情侣、养宠家庭与亲密小圈子的共同生活空间。

首页用“我回来啦”承接一天结束后回到家的情绪，再依次回答：

- 家里现在有什么要紧的事。
- 今天一起吃什么、照顾谁、完成什么。
- 共同生活里有哪些持续发生的数据。
- 最近有什么值得留下来的小事。

库存是第一条可落地的业务闭环，但不是整个产品的身份。当前版本用同一套本地持久化方式验证菜单、宠物和记录的真实操作手感；所有页面仍明确标注“本机 Demo”，不伪装成已同步能力。

## 3. 信息架构

底部保留四个核心入口：

| 入口 | 页面职责 | Demo 1.1 状态 |
| --- | --- | --- |
| 家 | 今日概览、库存提醒、菜单与宠物摘要、最近记录 | 读取各模块本地数据 |
| 库存 | 到期分组、筛选、物品列表、新增、详情与历史恢复 | 本地 Mock 数据闭环 |
| 记录 | 生活点滴、重要记录、可见性和记录增删改查 | 本地 Mock 数据闭环 |
| 我的 | 当前身份、共同空间、成员、待办入口、邀请、提醒设置和 Demo 工具 | 本地交互与全量 Demo 重置 |

“家”必须是默认入口。用户不需要先理解功能模块，先看到共同生活正在发生什么，再进入具体事务。

## 4. 核心页面

### 家

- 根据上海时区显示问候、日期和星期。
- 汇总库存里已过期或临期的数量，形成一条“家里要紧的事”。
- 用时间顺序组织库存、晚餐和宠物照护，而不是堆放功能卡片。
- 展示库存、宠物、菜单和共同生活天数四个长期模块，并可进入菜单和宠物体验页。
- 通过最近一条生活记录把工具信息重新落回日常感受。

### 库存

- 摘要使用紧凑的圆角状态卡，物品仍使用易扫描的连续清单。
- 状态颜色只帮助扫描，必须同时保留“已过期 N 天”“还剩 N 天”等文字。
- 新增、编辑、用完、丢弃、归档、历史恢复和重置均保留本地交互。

### 记录

- 以日期和时间轴组织生活点滴，体现“共同记忆”而非社交动态流。
- 生活点滴和重要记录都支持新增、查看详情、编辑和删除，内容、可见范围与更新时间保存在本地。
- 重要记录按“家的资料 / 健康资料 / 宠物资料 / 其他资料”分组，适合保存需要长期查找的信息。
- 明确哪些内容对空间成员可见，为后续权限模型留出位置。

### 我的与空间

- “我的”页同时表达个人身份和当前共同空间，不把两类信息混在一起。
- 空间页展示名称、成员、角色、邀请规则和隐私边界。
- 空间名称、邀请码刷新、复制、微信分享和接收方页面预览支持本地操作。
- 邀请落地页支持分享路径自动带码、手动输入、格式校验和当前设备防重复接受；真实邀请、成员权限与订阅消息仍由后端完成。

### 待办与小计划

- “我的”页提供“待办与小计划”入口，并显示未完成数量和旅行准备数量；进入后可在全部、旅行准备、小计划、健身、今天吃什么和我们的账单之间筛选。
- 一个统一表单承载五类记录：旅行为目的地、出发日期和逐项准备清单；小计划为日期和补充说明；健身包含运动、时长与按运动类型粗略估算的热量；吃饭包含餐次、备注和本地“换一个”推荐；账单包含金额、购买地点与买了什么。
- 列表支持直接勾选完成、逐项勾选旅行准备清单、点击编辑和长按删除；已完成事项排在后面，过期日期会明确标注。
- 账单按“已记账”保存并显示累计金额，不计入“还有几件没做”；健身热量按运动类型和时长粗略估算且可手动调整，只作日常记录，不作为医学建议。
- 所有待办、清单勾选和账单数据使用独立的本地存储键，刷新与重新进入后仍然存在。

### 宠物

- 顶部支持在多个宠物档案之间切换，也可新增猫、狗或其他伙伴；首页始终读取当前宠物。
- “档案”集中展示出生、到家、绝育、体重和成长事件时间线。
- “照护”持续记录内外驱，并按照 90 天和 30 天 Demo 周期推算下次日期。
- 独立事件表单支持事件类型、日期、标题、备注、机构、费用和下次计划。
- 时间线和月历中的真实事件可进入详情，并支持编辑和删除；修改会同步反映在两个入口。
- 宠物月历按月展示历史事件、明确的下次计划和周期照护日期，并可从选中日期继续新增记录。
- “吃喝拉撒”按上海自然日汇总进食、饮水、便便和尿尿，可重复记录次数和最近情况。
- “吃喝拉撒”管理主粮、罐头、冻干、汤包和猫砂集合，条目可在正在用、爱吃、吃过、种草和拔草之间切换。
- 首页宠物卡读取同一份本地状态，展示最新体重和优先级最高的内外驱提醒。
- 医疗相关内容只作生活记录，页面明确提示不构成诊疗建议。

### 表单与详情

- 保留库存本地闭环所需的新增、编辑和详情操作。
- 菜单支持详情、人份调整、食材备料勾选和表单编辑；重要记录复用同一套记录详情与编辑机制。
- 视觉沿用 v4.6「冷柔光纸面」，输入区域使用清晰字段分组和统一细线图标。

## 5. 视觉基线

> 2026-10-24 起以 v4.6「冷柔光纸面」为准；旧版视觉描述已被本节替代。

整体方向是“有温度的编辑式家庭账本”：冷柔光纸面、墨色正文、柔和靛蓝数据强调、细线分隔。克制不等于拒绝影像，图片只在承载情绪或内容时出现，不作为装饰背景。空态、邀请和身份收尾可以使用克制的小幅公版插画，并就近标注来源。统一细线图标让长列表、表单与详情不只依赖文字识别。

| 角色 | 取值或原则 |
| --- | --- |
| 页面底色 | `#f6f4f9`，冷柔纸面 |
| 主文字 | `#22242e`，近墨黑 |
| 主强调色 | `#5b6ee0`，柔和靛蓝，只用于日期、数量和行动提示 |
| 状态色 | 低饱和绿、暖黄和珊瑚红；状态始终保留文字 |
| 内容容器 | 以无边框、细线分隔为主；只有确实需要成组时才使用弱边框容器 |
| 图片 | 每页最多一个叙事影像锚点；满宽或图文并置，无圆角、无投影，并标注示例/来源 |
| 小幅插画 | 只用于空态、邀请和身份收尾；单张高度不超过正文区约三分之一，不抢占首屏任务 |
| 功能图标 | 统一使用 Lucide Static 0.468.0 线性图标，常规尺寸 22–32rpx；辅助文字识别，不单独承担关键操作 |
| 底部导航 | 纸面同色固定底栏，线性图标 + 文字，选中态提高墨色对比 |

后续页面应避免：

- 高饱和颜色铺满整张页面。
- 每张卡片都使用同一种颜色和尺寸，导致没有层级。
- 只用颜色区分业务状态而不保留状态文字。
- 过重阴影、发光、玻璃效果和装饰性图片背景。
- 直接使用系统 emoji，导致不同设备视觉不一致。
- 每个模块都使用“标题 + 描述 + 立即体验”的生成式模板结构。
- 把公版艺术示例伪装成用户真实照片；涉及宠物、物品和记录时必须明确标注。
- 每个空态都强行配图，或把插画当作填充留白的装饰贴纸。
- 把每个标题、字段和按钮都配图标，形成拥挤的图标墙。

## 6. 数据与后端边界

当前目录统一为 `src/`，不再使用 `miniprogram/`。

库存通过 `InventoryGateway` 接口访问本地 Mock 实现，并持久化到小程序本地存储。首页只读取该接口返回的库存摘要，因此后端接入时无需重写页面结构。多个宠物档案、当前宠物标识、事件、体重、每日吃喝拉撒和用品集合使用一份独立的本地容器；旧版单宠物数据会在首次读取时自动迁移。生活记录、提醒偏好、当前邀请码和已接受邀请码也使用独立的本地存储键，避免相互污染。

菜单、生活记录／重要记录、待办、宠物、提醒和邀请分别使用独立的本地存储键维护 Demo 数据。所有页面都明确保留本机 Demo 提示，不提前设计无法验证的服务端接口。

后端完成后，先用 HTTP 实现替换库存 Gateway，再依次接入登录、空间和邀请。OpenAPI 是前后端唯一接口契约。

## 8. 本地运行与校验

```bash
npm install
npm test
npm run typecheck
npm run verify:demo  # 需先开启开发者工具自动化端口
npm run test:coverage
npm run icons:build  # 仅在修改 assets/lucide-icons 后执行
```

然后在微信开发者工具中导入仓库根目录。`project.config.json` 已将 `miniprogramRoot` 和 `srcMiniprogramRoot` 指向 `src/`。

自动化测试覆盖日期和到期规则、库存本地仓储、首页问候与摘要组合、子页返回、库存历史操作、生活记录／重要记录格式化与本地增删改查、菜单字段规范化与本地增删改查、旅行清单与五类待办字段规范化、账单和待办持久化、邀请码规范化与分享路径，以及宠物年龄、时间线、内外驱周期、每日吃喝拉撒汇总、用品筛选、月历、事件读写删除和旧数据迁移等逻辑。`verify:demo` 会连接微信开发者工具，实际验证重要记录、菜单和待办的增删改、清单勾选、刷新持久化与全量重置。

## 9. 视觉验收清单

- 打开即进入“家”，首屏主标题是“我回来啦”。
- 四个 Tab 分别是家、库存、记录、我的。
- 自定义底部 Tab 不遮挡最后一条内容或悬浮操作按钮，带底部安全区的设备也应保留足够间距。
- 菜单、宠物、记录表单、空间和提醒设置页能够返回来源页；直接打开子页时能够回到对应 Tab。
- 空间页可以复制和分享当前邀请码，邀请分享路径能打开接收方页面并自动完成格式校验。
- 同一个邀请码在当前设备接受后显示已加入状态，不能重复执行接受操作。
- 宠物页可在档案、照护和吃喝拉撒之间切换，新增记录后重新进入页面仍然存在。
- 宠物页可切换示例伙伴，新增伙伴后首页和宠物页均读取当前档案。
- 事件表单可保存机构、费用与下次计划；月历能在跨月切换后显示对应日期的事项。
- 时间线和月历均可进入事件详情；编辑或删除后，返回来源页面时内容即时更新。
- 重要记录可切换分类、可见范围并完成新增、详情、编辑和删除，重新进入页面后内容仍存在。
- 菜单可完成新增、详情、编辑和删除；人份与食材备料勾选在返回、重进和编辑后保持。
- “我的”页的“待办与小计划”显示准确未完成数量；五类分类均可查看、新增和完成，重新进入后状态仍在。
- 旅行待办可填写目的地、日期和多行准备清单，清单项可逐项勾选；账单可记录金额和购买地点，且不计入未完成待办。
- “恢复 Demo 初始数据”后库存、宠物、记录、菜单、待办、提醒和空间名称都回到可识别的初始状态。
- 内外驱的最近日期和下次日期随新增记录更新，过期和临近状态同时保留文字提示。
- 主粮、罐头、冻干、汤包和猫砂可筛选，集合状态可修改。
- 进食、饮水、便便和尿尿可在同一天重复记录，今日次数、最近内容和时间即时更新。
- 页面在小屏设备上没有横向溢出、文字截断或底部 Tab 遮挡。
- 首页信息能按“今天状态 → 晚餐 → 生活数据 → 最近记录”顺序阅读。
- 库存状态在不依赖颜色的情况下仍可理解。
- 静态预览能力不会让用户误以为可以保存或同步数据。
- 界面不依赖圆角卡片和投影，层级由字号、留白与细线建立。
- 叙事大图每页最多一处；小幅插画只出现在空态、邀请和身份收尾，并保持统一墨色。
- 所有公版艺术示例均有就近标识，作品与授权信息可在 `assets/credits.json` 追溯。
- 图标风格、线宽和尺寸一致，常规区域不出现图标替代文字或图标密度过高的情况。

## 10. 下一阶段

前端本地 MVP 已具备可讨论的操作深度。下一阶段先完成后端第一个垂直切片：微信登录、默认空间和库存读取。接入期间保持页面叙事不变，仅将本地 `InventoryGateway` 替换为 HTTP 实现；菜单、宠物、记录和提醒继续保留本机 Demo，直到各自数据模型和同步范围被单独确认。
