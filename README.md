# 时刻在

> 我回来啦，把日子安放在一起。

时刻在是一个面向家庭、情侣、养宠家庭与亲密小圈子的共同生活管理小程序。

项目的核心不是单一的库存清单，而是一个可共享的生活空间：成员可以管理家庭物品和有效期、宠物档案、个人健康数据、菜谱与菜单、生活点滴，以及重要的图文记录。

当前仓库是微信小程序前端工程。配套 Go 服务端在 `popcorn-server` 仓库维护，双方通过版本化 HTTP API 通信。

## 当前状态

项目当前为前端 v1.4：以“家”为首页，采用 v5「柔光玻璃生活手帐」视觉。登录注册、个人中心、库存、宠物、菜单、生活点滴、重要记录、待办与小计划、提醒设置、共同空间和邀请均有可操作界面。B1/B2 已将账号、资料、会话、默认空间、空间成员和单次邀请接入真实 Go API；后端 B3 + 前端库存网关、后端 B4 + 前端待办网关均已完成。当前支持 Demo/HTTP 双模式、双账号共享库存与待办、版本冲突处理、幂等写入、生命周期、软删除恢复和网络异常兜底；菜单、宠物、生活记录和提醒仍保留本机 Demo。`src/config/env.ts` 可切换 Demo 与 HTTP 模式，正式构建会关闭 Demo。旧版小程序和云函数实现已移除。

## 技术决策

- 前端：微信原生小程序，使用 TypeScript、WXML 和 WXSS。
- 后端：独立 Go 模块化单体服务，不使用旧版微信云函数实现。
- 数据库：复用现有服务器 MySQL，使用独立数据库和独立账号。
- 文件存储：已有腾讯云 COS；当前先规划数据库备份与后续用户媒体，图片上传尚未进入主链路。
- 部署：不依赖 Docker。GitHub Actions 构建 Linux 二进制，服务器通过 systemd 运行 Go API，现有 Nginx 提供 HTTPS。

## 本地开发

使用微信开发者工具导入本目录即可运行 Demo。首次拉取后执行：

```bash
npm install
npm test
npm run typecheck
npm run verify:demo  # 需先开启开发者工具自动化端口
```

真实接口联调时，把 `src/config/env.ts` 临时切为 `demoMode: false`、`apiBaseUrl: http://127.0.0.1:8080`，启动本机 API 后执行：

```bash
npm run verify:http-b2
npm run verify:http-b3
npm run verify:http-b4
```

`b2` 用两个 mock 微信身份验证注册、会话、空间、邀请和单次失效；`b3` 验证双账号共享库存、前端创建编辑、版本冲突、状态流转、软删除恢复和摘要更新；`b4` 验证双账号共享待办、准备项勾选、完成/重开、账单自动完成、旧版本冲突恢复和软删除。API 不在 8080 时可通过 `API_BASE_URL` 覆盖。联调完成后切回 `production` + `apiAuthMode: 'wechat'` 再编译。账号、资料、空间、邀请、库存和待办已支持 HTTP 模式；宠物、菜单、生活记录和提醒仍使用本地存储。小程序包由微信平台编译和发布，CDN 不用于承载小程序代码。

## 仓库边界

本仓库只维护小程序客户端。配套的 `popcorn-server` 仓库用于维护 Go API、数据库迁移、Linux 发布产物和 systemd 服务器部署配置。
